## SABR — версия 1.4.0

Реализован путь SABR/UMP через нативный запрос страницы. Параметры сессии запрашиваются только в момент скачивания и не записываются в storage.session вместе с очередью. Две дорожки записываются в OPFS; LibAV читает их через mkreadaheadfile, поскольку WORKERFS отсутствует в поставленном бинарнике.

Модульные тесты проверяют разделение UMP на видео/аудио, сохранение клиентского контекста и уже выданного токена, немедленную остановку при отказе подтверждения, ограничение запросов текущим видео, HTTP 403 и сохранение исходного тела Request при наблюдении. Браузерный тест на настоящих H.264/AAC-данных проверяет сборку целого MP4 с обеими дорожками. Полный мост страницы проверяется на синтетической странице YouTube с перехваченными локальными UMP-ответами; это не проверка реального сервиса или сессии пользователя.

Итоговая проверка 1.4.0: 37 модульных тестов и 31 браузерный сценарий прошли. В полном синтетическом сценарии SABR сохранено 45271 байт, подтверждены H.264 и AAC. Реальная ссылка JPHT9AvoPSA остаётся непроверенной в авторизованной сессии пользователя.


## Финализация SABR — версия 1.4.1

Воспроизведён сброс размера: после получения двух дорожек счётчик переключался на размер ещё пустого выходного файла и возвращался к статусу downloading. Полученные байты, размер результата и байты копирования теперь учитываются отдельно; размер полученных данных не уменьшается, а локальная сборка отображается как finalizing.

Длинная фикстура выявила медленную работу CLI FFmpeg: объединение 4-минутного ролика не завершалось за 30 секунд даже после замены Blob-чтения. Для SABR CLI заменён прямым переносом медиапакетов через API LibAV. Пакеты обеих дорожек чередуются по DTS, временные базы пересчитываются, отрицательное начало нормализуется общим сдвигом. Чтение OPFS использует синхронный блоковый кэш по 1 МБ на дорожку; в памяти ограничен один небольшой пакетный буфер на дорожку.

Локальный браузерный результат: H.264/AAC, длительность 256.912 с, MP4 5232753 байта; финализация 397 мс. Проверено отсутствие уменьшения счётчика и возврата в downloading после начала finalizing. Это измерение локального этапа сборки, а не скорости реального YouTube.

Финальная проверка 1.4.1: 43 модульных теста и 33 браузерных сценария прошли, включая MP4 и MKV. Повторный длинный тест: MP4 5274261 байт, длительность 258.4825 с, локальное объединение 378 мс.

## Живой прогресс — версия 1.4.3

Сетевые ответы Worker обёрнуты потоком подсчёта байтов с сохранением URL, HTTP-статуса и заголовков диапазона. Прогресс больше не зависит от завершения блокирующего опроса CLI. Во время SABR учитываются размеры двух выбранных дорожек или общая полученная длительность видео и звука; 100% передаётся после успешного завершения приёма. Длительность карточки Instagram используется, если её нет в манифесте. Панель обновляется по уведомлениям сервиса и показывает численный процент рядом с полосой; без точного процента используется неопределённый индикатор.

## Привязка роликов Instagram — версия 1.4.4

Устранена привязка всех источников к адресу открытого Reel. Каждая запись использует собственный shortcode или media ID; предзагрузка следующего ролика не заменяет текущий. Записи без идентификатора больше не связываются с текущим видео по случайному положению в HTML. Найденные соседние ролики остаются отдельными карточками; текущий показывается первым с отметкой «Текущий Reel». При прокрутке найденные записи сохраняются, а отметка обновляется. Числовой ID и shortcode объединяются только при явной связи в метаданных или точном совпадении ID с декодированным shortcode открытого адреса. Соответствие shortcode и media ID сверено с первичным кодом Instaloader: https://github.com/instaloader/instaloader/blob/master/instaloader/structures.py (shortcode_to_mediaid).

Браузерная проверка моделирует три Reel, некодированную предзагрузку, поздний JSON-ответ и посторонний анонимный DASH в HTML. Подтверждены три карточки, единственная отметка текущего и побайтовое совпадение скачанных текущего и следующего роликов с выбранными источниками. Это локальный синтетический сценарий, а не проверка аккаунта пользователя.

Итоговая проверка 1.4.4: 55 модульных тестов и 37 браузерных сценариев прошли. Дополнительно проверены точные строковые ID при небезопасных числовых PK и сохранение доказанной связи ID/shortcode при частичных обновлениях.


## Прокрутка и сохранение Instagram — версия 1.4.5

При history-переходах Instagram обнаруженные карточки больше не удаляются. Перехватываются pushState/replaceState/popstate, добавлено ограниченное по частоте сканирование scroll и принудительный snapshot без потери события в 500-мс фильтре.
