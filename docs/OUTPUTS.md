# Тип результата: видео и будущее аудио

`domain/media-output.ts` отделяет намерение скачивания от транспорта источника. `Media.kind` описывает HTTP/HLS/DASH/SABR и пары дорожек; `MediaOutput.kind` описывает видео или аудио, а `container` — целевой контейнер.

`DownloadRequest`, `ServiceContext`, `DownloadPlan` и `WorkerStart` передают этот контракт по цепочке очередь → обработчик сервиса → offscreen → Worker. Старые задачи без `output` читаются как видео с прежним контейнером. Явный запрос аудио никогда не преобразуется в запрос видео.

`outputPolicy` задаёт обязательность дорожек: для видео обязательна видеодорожка, для аудио обязательна аудиодорожка и исключается видео. `application/output-capabilities.ts` пока разрешает только видео. Типы аудиоконтейнеров описывают будущий контракт, но не означают готовую поддержку конвертации.

Интерфейс остаётся прежним: выбор MP4/MKV, без новых кнопок и режима аудио. Для включения аудио понадобятся реализация выбора/извлечения аудиодорожки в обработчиках, согласование кодеков и контейнера в Worker, отдельная проверка результата и тесты. Затем можно включить capability и добавить интерфейс отдельно.
