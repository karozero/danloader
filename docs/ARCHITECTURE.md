# Архитектура и границы доверия

## TypeScript и модули

Исходники приложения находятся в `src/**/*.ts`. Команда `npm run build` сначала выполняет `npm run typecheck`, затем esbuild выпускает JavaScript и source maps в `dist`. Manifest и HTML ссылаются на скомпилированные `.js`. Content scripts собираются в IIFE, остальные точки входа — в ES modules.

- `domain/media.ts` — контракты источников, вариантов качества, задач, сохранения и сообщений Worker. `domain/media-output.ts` отделяет целевой тип видео/аудио от транспорта; [подробности](OUTPUTS.md).
- `application/` — координация обработчиков сервисов, кэш качеств, параллельное скачивание дорожек и обновление прогресса. Получение дорожек и запись передаются функциями.
- `services/` — отдельные методы скачивания YouTube, Instagram, Boosty и общий обработчик; [контракт и расширение](SERVICES.md).
- `core/` — общий разбор HLS/DASH, группировка кандидатов и проверка MP4.
- `infrastructure/` — IndexedDB/File System Access, OPFS, LibAV, загрузка манифестов и обмен с offscreen-документом.
- `presentation/language.ts` — локализация; `popup.ts` управляет интерфейсом, `presentation/destination-picker.ts` — выбором папки.
- Корневые `service.ts`, `content.ts`, `page.ts`, `youtube-session.ts`, `offscreen.ts` и `worker.ts` связывают окружение расширения с модулями.

`tsconfig.json` охватывает все исходники приложения. Для совместимости с динамическими объектами плееров пока разрешены неявные `any`, отключены `strictNullChecks` и `noImplicitThis`. Полного строгого режима для всего проекта пока нет. Поставляемые LibAV/WASM не преобразуются.

`npm test` пересобирает приложение и запускает модульные проверки над результатом сборки. `npm run verify` также проверяет скачивание и переключение языка в изолированном Chrome.


## Путь данных

1. `content.js` находит HTML video/source; `page.js` читает выбранные публичные данные плееров и ограниченный объём встроенного JSON.
2. `service.js` наблюдает ответы webRequest, связывает кандидаты с вкладками, дедуплицирует их и хранит краткоживущее состояние в storage.session.
3. Только страница интерфейса расширения может начать, отменить или остановить загрузку. Сообщения от web-страниц содержат только кандидатов и проходят проверку схемы, URL, объёма и актуальности документа.
4. `offscreen.js` передаёт анализ и подготовку потока в `application/download-engine.ts` и обработчик выбранного сервиса; затем создаёт отдельный Worker на задачу.
5. `worker.js` скачивает прямой файл потоково либо вызывает LibAV для HLS/DASH/объединения. Синхронный OPFS writer пишет по смещениям; весь выходной файл не собирается в RAM.
6. При выборе папки браузера offscreen создаёт Blob URL для готового OPFS File, а сервис сохраняет его через chrome.downloads. При выборе общей папки offscreen потоково копирует результат в неё через File System Access API.
7. После завершения, отмены или ошибки удаляются временный файл, Blob URL, Worker и правила заголовков. При создании нового offscreen-документа очищаются остатки предыдущего запуска.

## Обнаружение целого видео (1.1.0)

`page.js` наблюдает конфигурацию `vk-video-player.initPlayer` и данные `playerUrls`, которые уже переданы доступной пользователю странице Boosty. Оригинальный метод вызывается с прежними аргументами и возвращаемым значением. Метаданные включают ID, длительность, обложку и форматы целого ролика. Состояние с `hasAccess:false` пропускается; отдельные API для получения закрытого контента не вызываются.

Ответы fetch/XHR с HLS/DASH пассивно читаются через копию тела с ограничением 1 МБ. Сервис также может запросить сам манифест, чтобы восстановить его ссылки. `core/discovery.js` связывает master, варианты и сегменты; позднее появление master скрывает ранее обнаруженные фрагменты. Стандартные сегментные расширения и initialization-файлы исключаются. У сетевых файлов учитывается полный Content-Range, а не длина отдельного ответа. Дополнительный порог мелких сетевых ответов не применяется к явно указанному видео со страницы.

Форматы одного ID плеера и связанные HLS/DASH/HTTP-запросы показываются одной карточкой. Список проверяется в пределах документа/фрейма, чтобы поток в одном iframe не скрывал независимое видео в другом. В версии 1.2.0 показана только обложка; генерация видео-превью исключена.

## Общая папка сохранения (1.2.0)

Вверху панели доступны две кнопки: «Загрузки» выбирает папку браузера по умолчанию, «Выбрать» открывает системный диалог напрямую из панели. Дополнительное окно расширения не создаётся. `showDirectoryPicker({mode:'readwrite'})` вызывается непосредственно обработчиком нажатия. Выбранные DirectoryHandle и активная настройка хранятся локально в IndexedDB; через сообщения Chrome передаются только ID и имя папки. Нативный handle сохраняется структурированным клонированием, а не сериализацией в JSON.

При постановке задачи в очередь проверяется разрешение на запись и фиксируется выбранный destination ID. Поэтому изменение общей папки влияет на новые задачи; уже поставленные задачи используют прежнюю папку. Потеря разрешения показывается до старта загрузки, без скрытого перехода к другому месту сохранения. Завершённый файл переносится потоково, существующие имена сохраняются за счёт суффиксов `(1)`, `(2)`. При отмене записи её незавершённый файл удаляется.

## Очередь и жизненный цикл

Один активный Worker; до 50 ожидающих задач с дополнительным ограничением объёма их данных. Изменения очереди сериализованы. Очередь и состояние сохраняются в storage.session до запуска задачи. Перезапуск фонового service worker не перезапускает работающий offscreen Worker. При отсутствии соответствующей активной задачи после восстановления показывается ошибка, а не ложное завершение. После полного закрытия браузера автоматического возобновления нет.

## Заголовки и конфиденциальность

Cookie/Authorization/Referer/Origin могут потребоваться CDN для получения того же медиа, которое воспроизводит страница. Захваченные заголовки находятся только в памяти сервиса, ограничены по количеству и сроку (10 минут). В очередь и storage.session они не записываются.

Временные DNR-правила применяются только к запросам с инициатором ID этого расширения и точным origin источника. Cookie и Authorization не переносятся на другой origin. Для дополнительных CDN могут переноситься только Referer/Origin; если для них были наблюдены собственные заголовки, используются они. При смене активной задачи правила заменяются.

URL видео могут содержать подписанные токены и находятся в storage.session вместе с кандидатами и очередью. Контент-скриптам закрыт прямой доступ к session-хранилищу. Постоянная история, установочный идентификатор и аналитические счётчики отсутствуют. Настройка папки и ссылки на выбранные папки сохраняются в локальной IndexedDB. Локальные отчёты тестов используют только синтетические URL localhost.

## Разрешения

| Разрешение | Использование |
|---|---|
| downloads | Сохранение итогового файла и отслеживание завершения |
| storage | Состояние текущей сессии и очередь |
| webRequest | Обнаружение видео/манифестов и нужных заголовков |
| webNavigation | Сброс результатов после навигации и проверка документа отправителя |
| offscreen | Worker и сохранение Blob независимо от открытой панели |
| declarativeNetRequest | Временные заголовки для запросов к источникам медиа |
| unlimitedStorage | Временные большие файлы OPFS |
| HTTP/HTTPS host access | Страницы и отдельные CDN, включая iframe |

Нет nativeMessaging, browsingData, notifications, sidePanel, contextMenus, downloads.open и собственного обновляющего сервера. Нет автоматически открываемых внешних страниц. Весь исполняемый код поставляется локально. Разрешение host access широкое для универсального обнаружения; замена его на разрешения отдельных сайтов требует отдельного режима работы.

## Происхождение

Приложение реализовано на TypeScript и собирается в локальные JavaScript ES modules/IIFE. Движок SABR из npm-зависимости googlevideo включается в сборку. Из исходного расширения перенесены только два библиотечных файла LibAV/WASM. Изменения минифицированных бандлов исходного приложения не выполнялись. `docs/original-inventory.json` фиксирует 81 исходный файл. Полная реконструкция исходников самого WASM и воспроизводимая компиляция этого движка не выполнены.
