# Обработчики сервисов

## Структура

- `src/services/contracts.ts` — общий контракт `DownloadService` и порты окружения.
- `src/services/registry.ts` — выбор обработчика по URL.
- `src/services/youtube/` — обновление ссылок, выбор формата по ID, однократное повторение при 403, native SABR и разбор ответа плеера.
- `src/services/instagram/` — группировка качеств, inline DASH и подготовка полных видео- и аудиодорожек.
- `src/services/boosty/` — скачивание выбранного качества сгруппированного видео плеера.
- `src/services/kinescope/` — обнаружение текущего видео внутри iframe, превью, качества и подготовка HLS/DASH, в том числе на Sponsr.
- `src/services/generic/` — HTTP, HLS и DASH для остальных страниц.
- `src/services/shared/` — общий разбор манифестов и раскрытие выбранного варианта без дублирования транспортного кода.
- `src/application/download-engine.ts` — координация обработчиков, проверки отмены/DRM и кэш анализа.
- `src/assets/flags/` — локальные SVG-флаги интерфейса.

## Маршрутизация и очередь

Реестр сначала проверяет URL фрейма, которому принадлежит видео, затем URL текущей вкладки, затем URL самого источника. Совпадения доменов проверяются по hostname, а не подстроке: `youtube.com.evil.example` не считается YouTube.

URL вкладки получается через Chrome API при анализе или постановке в очередь и сохраняется в `Media.servicePageUrl`. Последующая навигация не меняет сервис уже поставленной задачи. Для сохранённых записей с адресом только CDN остаётся совместимость с ранее обнаруженной меткой сервиса/ID плеера. Известный URL имеет приоритет над такой меткой. Посторонние страницы сохраняют общий загрузчик.

## Контракт

- `inspect` возвращает качества и данные потока.
- `download` готовит точный план выбранного видео: медиа, вариант, длительность и признак трансляции.
- Необязательный `refresh` обновляет метаданные перед добавлением задачи.
- Необязательный `prepareQueued` обновляет истёкшие ссылки непосредственно перед запуском. YouTube сохраняет выбранный format ID даже при изменении порядка качеств.

Обработчик получает загрузку манифестов, подготовку заголовков и анализ через порты `ServiceContext`. Он не управляет Chrome UI, папками или жизненным циклом Worker. `offscreen.ts` запускает Worker по готовому плану и сохраняет результат. Физическая запись, прогресс, отмена и очистка временных файлов общие для всех сервисов.

Раскрытая проекция выбранного варианта анализируется заново, чтобы обновлённая подписанная ссылка не подменялась старым кэшем. Полные дорожки и исходные параметры качества сохраняются; рефакторинг не добавляет перекодирование.

## Добавление сервиса

1. Создать `src/services/<service>/downloader.ts` и реализовать `DownloadService`.
2. Добавить ID в `ServiceId`, домены в `services/hostnames.ts` и обработчик в список `services` реестра. `matchesServiceHost` проверяет точный hostname.
3. Использовать общие функции для HTTP/HLS/DASH и добавлять в модуль сервиса только его особенности.
4. Если нужны новые данные страницы, расширить обнаружение в `page.ts`/`content.ts`, сохраняя существующие проверки входящих кандидатов.
5. Добавить проверки URL, выбранного качества и полного файла, затем выполнить `npm run verify`.

Автоматические проверки используют синтетические локальные медиа и записанные структуры ответов. Живое скачивание с сайтов в этот прогон не входит.

## Общий поиск на неизвестных сайтах

`services/generic/discovery.ts` находит HTTP(S)-источники у `video` и вложенных `source`, включая открытые Shadow DOM. Альтернативные источники одного элемента объединяются в карточку. Замена адресов на переиспользованном элементе создаёт новую идентичность видео. Пустые адреса, `blob:`, `data:`, `javascript:` и обычные сегменты не выдаются за готовые видео.

Если прямых HTML-источников нет, на неизвестном домене проверяются явные медиассылки Open Graph и `VideoObject.contentUrl` из JSON-LD. HTML embed-страницы не считаются видеопотоками. Обход DOM/JSON ограничен по размеру и глубине.

Для MediaSource/`blob:` остаётся общий сетевой поиск HLS/DASH: манифест становится карточкой, а куски не показываются отдельными файлами. Поиск не создаёт доступ к потоку, который страница не предоставила. Указанный пример antonov.media не добавлен в реестр сервисов.

Будущее разделение видео/аудио описано в [OUTPUTS.md](OUTPUTS.md).

## Быстрый HLS VOD

`core/hls-static.ts` выделяет безопасный статический план. `application/download-hls.ts` загружает до четырёх сегментов одновременно, а `infrastructure/segment-spool.ts` хранит их на диске, ограничивая память и сохраняя порядок. `infrastructure/remux.ts` переносит готовые пакеты в MP4/MKV без запуска сетевого CLI и без перекодирования. Тот же remux сохраняет работу раздельных дорожек Instagram/SABR.

Зашифрованные, live и прерывающиеся плейлисты не переводятся на этот путь. Byte-range разрешён отдельно обработчиком Kinescope: запрашиваются точные диапазоны, проверяются HTTP 206, Content-Range и длина ответа. Для остальных сервисов сохраняется общий обработчик диапазонных плейлистов. Заголовки, подписанные URL и выбранное качество остаются исходными. Временные файлы освобождаются после успешной загрузки, ошибки и отмены.

Kinescope читает `playerOptions` только текущего iframe и объединяет его источники в одну карточку. Отдельный адаптер Sponsr не нужен: сервис выбирается по адресу вложенного плеера. Ограниченный по времени embed использует только фактически наблюдённый манифест фрагмента; ссылки на полное видео не подставляются.
